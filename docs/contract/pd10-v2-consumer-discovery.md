On branch `feat/story-1-17-v2-closure-prep`, the server host reads one validated setting, `Folders:ApiRouting:Mode`:

| Mode | Routes | Plan B use |
| --- | --- | --- |
| `V1Only` (default when the setting is absent) | v1 only. The pipeline is the same as before this change, and `/api/v2` has no route. | The hold (plan C) and the rollback target. |
| `Coexistence` | v1, plus v2 through the PD10 candidate compatibility seam. | The seven-day window, after every entry check passes. |
| `V2Only` | v2 through the seam. Every external `/api/v1` request, in any letter case, gets the canonical non-enumerating 404 before authorization, lookup, or effect. The host reads the mode once at startup, so every mode change needs a restart or redeploy. That includes a rollback or an incident "disable v2 exposure" step, and the rollback rehearsal should time it. An empty or unknown value stops host startup. `FoldersApiRoutingModeTests` boots the real host composition in each mode and covers the startup rejection. These tests prove branch behavior only. No production host has been deployed with this change, no mode has been switched, no T0 has been recorded, and the seven-day clock has not started. The v1 retirement still needs every exit check in the migration package, including evidence that no other v1 consumer is deployed.

## Route attribution and remaining discovery

The host emits `folders.api.requests`, `folders.api.errors`, and `folders.api.duration` from the existing registered meter `Hexalith.Folders.Observability`. Tags are limited to `api.version` (`v1` or `v2`), `consumer` (`projects`, `other`, or `unattributed`), and numeric `http.status_code`. The active request trace receives the same bounded route facts. The `projects` value requires an authenticated `client_id` or `azp` claim equal to `Hexalith.Projects`; an arbitrary request header cannot supply it. No folder, tenant, path, body, token, or raw consumer identifier is a metric or trace attribute. The collector and dashboard must retain these dimensions and request traces before route exposure. The pre-switch baseline must prove that production Projects traffic actually lands in `projects`; `unattributed` traffic cannot establish consumer absence.

The local Projects source inventory contains `GetFolderLifecycleStatusAsync` and `GetEffectivePermissionsAsync` in `FoldersProjectFolderDirectory`, plus `GetFolderFileMetadataAsync` in `FoldersProjectFileReferenceDirectory`. The folder calls run on project-folder validation and refresh; metadata runs on file-reference link validation. `RefreshFileReferenceAsync` makes no Folders call. This is a source inventory, not a complete production schedule or deployed-consumer census. Delivery must identify periodic job frequency and ordinary traffic for each call family from the deployed Projects artifact, and discover every other deployed v1 consumer from attributed production telemetry before retiring v1.
