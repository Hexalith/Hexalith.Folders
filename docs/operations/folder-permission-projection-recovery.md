# Folder permission projection recovery

The organization and folder permission rows are derived from retained Folders EventStore streams. If a row is missing after its event delivery was acknowledged, the authorization reader compares the missing row with the actor's current head. A nonzero head is reported as stale with no grant evidence. Mutations and strict reads remain unavailable until the row has caught up.

An operator can repair a missing, malformed, or incomplete row by replaying the **retained EventStore events** through the existing authenticated Workers `/folders/events` callback. This path applies the same payload-version, event-type, stream-identity, and contiguous-sequence checks as normal delivery. It does not create an ACL grant or change an EventStore stream.

1. Identify the tenant and actor aggregate ID from the authoritative stream. The organization baseline actor uses the tenant ID. A folder actor uses its folder ID. A provider-binding actor has no permission row and must not be repaired as a folder. Keep the Folders Server unavailable to callers from the start of a row reset until verification finishes, so an incomplete but well-formed old row cannot authorize a stale grant. Pause normal Workers deliveries for the target stream while establishing the replay point.
2. For a **present** row, capture its ETag and conditionally erase only its derived key in `statestore`: `projection:folders:organization-permissions:{tenantId}` for the baseline or `projection:folders:folder-permissions:{tenantId}:{folderId}` for a folder. Use the EventStore SDK `IReadModelConditionalEraser.TryReadEtagAsync` and `TryEraseAsync` (or an operator state-store tool with the same first-write-wins ETag condition). If the ETag changed, stop and reassess; never use an unconditional delete. Read the key back and require absence before replay. Never erase the authoritative actor stream, an idempotency row, or a provider-binding actor row.
3. Use an authorized EventStore stream-read client to call `POST /api/v1/streams/read` for `tenant`, `domain: "folders"`, that `aggregateId`, `fromSequence: 0`, and a bounded `pageSize`. Continue from each page's `lastSequenceReturned` until the captured head is covered. Require contiguous sequence numbers starting at 1. Stop on missing, unreadable, or unsupported events. The stream-read response verifies the retained application logical digest and preserves the stored payload version; do not fall back to raw state-store bytes.
4. Establish an explicitly authorized **operator maintenance connection to the Workers application**, using `kubectl --namespace hexalith-production port-forward --address 127.0.0.1 pod/<selected-folders-workers-pod> 18080:8080`. Obtain operator authorization to read the selected pod and create `pods/portforward` in that namespace, to read the `hexalith-folders-workers-app-token` secret's `token` key, and to perform the stream read and conditional derived-row erase above. Normal service invocation to Workers remains denied: its Dapr policy has no allowed callers. Do not add a Dapr allow rule or forward the sidecar port. Restrict the port-forward to loopback and close it when repair finishes.

   Authenticate every local `POST http://127.0.0.1:18080/folders/events` with the existing per-workload app-channel token in the `dapr-app-token` header. Retrieve that token into the maintenance client's memory using the approved Kubernetes secret API; never print it, put it in a shell argument/history, store it in a replay file, enable HTTP header tracing, or include it in evidence. The application and sidecar use the same `hexalith-folders-workers-app-token` secret. Missing or wrong tokens must return 401 and leave the derived row unchanged; verify denial before submitting authenticated repair events. A public Folders bearer token cannot authorize this connection.

   For each digest-verified `StreamReadEvent` in order, send its exact retained `payload` bytes (base64-encoded as the callback envelope requires) and stored `eventTypeName`, `sequenceNumber`, `messageId`, `serializationFormat`, `metadataVersion`, and `payloadVersion`. Set `domain` to `folders`, `tenantId` and `aggregateId` to the stream-read request identity, and copy `timestamp`, `correlationId`, and `causationId` where present. Never synthesize a grant or edit retained payload bytes.
5. Verify each callback succeeds before sending the next event. A sequence gap, conflicting replay, unsupported version, or identity mismatch returns a failure and leaves authorization unavailable. Investigate the retained stream; do not skip the event.
6. Read the permission row and actor head again. Resume normal Workers delivery and Folders Server authorization only when the row's `LastSequence` equals the actor head, the row identity matches the tenant and actor, and the rebuilt grants match the retained ACL events. If new events arrived during repair, continue replaying the new retained range until current.

The callback applies permission events before the generic subscription marker check, so an acknowledged delivery can be replayed to rebuild a missing row. The route test deletes a folder row, confirms an unauthenticated replay cannot restore it, and then restores it with the identical authenticated retained envelope. It also proves that replay against a present incomplete row fails, an outdated ETag cannot erase it, and a conditional reset followed by replay removes the stale override. These are HTTP route and persisted-state tests, not a live Kubernetes repair exercise. This procedure requires operator access to EventStore stream read, the derived-row ETag eraser, and the Kubernetes-authorized, token-authenticated application maintenance connection; access to the public Folders REST API alone cannot replay permission events.
