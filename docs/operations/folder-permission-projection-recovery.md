# Folder permission projection recovery

The organization and folder permission rows are derived from retained Folders EventStore streams. If a row is missing after its event delivery was acknowledged, the authorization reader compares the missing row with the actor's current head. A nonzero head is reported as stale with no grant evidence. Mutations and strict reads remain unavailable until the row has caught up.

Production `concurrency: 1` is per component instance. Multiple replicas, restart, and reclaimed deliveries can still reorder retained events; neither the retry policy nor the concurrency setting guarantees global ordering. A rejected sequence gap leaves the projection unchanged. Retain the owner-approved bounded retries and dead letters, then deliver the missing range and retry the rejected envelope in retained order through the repair path below. There is no automatic global ordering or live broker restart proof in the route tests.

An operator can repair a missing, malformed, or incomplete row by replaying the **retained EventStore events** through the existing authenticated Workers `/folders/events` callback. This path applies the same payload-version, event-type, stream-identity, and contiguous-sequence checks as normal delivery. Operators must replay only digest-verified retained bytes: never synthesize a grant, edit a payload, or use this privileged callback to introduce authority. The callback validates shape, identity and order; its token is a trusted channel credential, not independent proof of retained origin.

1. Identify the tenant and actor aggregate ID from the authoritative stream. The organization baseline actor uses the tenant ID. A folder actor uses its folder ID. A provider-binding actor has no permission row and must not be repaired as a folder. Put the gateway command ingress into the deployment's maintenance deny rule, and scale `hexalith-folders-server` to zero replicas with `kubectl --namespace hexalith-production scale deployment/hexalith-folders-server --replicas=0`; save the prior replica count. Keep Folders unavailable until verification finishes. To pause broker delivery while retaining the Workers application and state-store sidecar, use an authorized Kubernetes client to change only the `subscriptionScopes` metadata entry of Component `folders-workers-pubsub` to `folders-workers=`. Preserve all broker connection metadata and credentials. Run `kubectl --namespace hexalith-production rollout restart deployment/hexalith-folders-workers`, then `kubectl --namespace hexalith-production rollout status deployment/hexalith-folders-workers`. Require all previous subscriber pods to terminate and confirm the replacement sidecars have no tenant or folder subscriptions before reset. This pause covers all Workers streams; coordinate the maintenance window accordingly. Do not reset a row while any normal subscriber remains active.
2. Establish the authorized, loopback maintenance connection described in step 4. For a **present** row, first `POST /maintenance/folder-permissions/reset` with `{ "tenantId": "<authoritative tenant>", "aggregateId": "<actor id>" }`. The token-authenticated route reads its ETag through EventStore SDK `IReadModelConditionalEraser.TryReadEtagAsync` without deserializing a malformed row and returns `{ "present": true, "etag": "<captured ETag>" }`. Submit the same identity with `expectedEtag` set to that returned ETag. The route uses `TryEraseAsync`, returns 409 if the present row changed, and requires absence on read-back before returning 204. Stop and reassess on 409; never request an unconditional erase. For an absent row the inspection returns `present: false`; proceed directly to replay. The route derives only `projection:folders:organization-permissions:{tenantId}` or `projection:folders:folder-permissions:{tenantId}:{folderId}` in `statestore`, rejecting provider-binding and reserved non-folder IDs. It cannot select an authoritative stream or idempotency key for erasure.
3. Use an authorized EventStore stream-read client to call `POST /api/v1/streams/read` for `tenant`, `domain: "folders"`, that `aggregateId`, `fromSequence: 0`, and a bounded `pageSize`. Continue from each page's `lastSequenceReturned` until the captured head is covered. Require contiguous sequence numbers starting at 1. Stop on missing, unreadable, or unsupported events. The stream-read response verifies the retained application logical digest and preserves the stored payload version; do not fall back to raw state-store bytes.
4. Establish an explicitly authorized **operator maintenance connection to the Workers application**, using `kubectl --namespace hexalith-production port-forward --address 127.0.0.1 pod/<selected-folders-workers-pod> 18080:8080`. Obtain operator authorization to read the selected pod and create `pods/portforward` in that namespace, to read the `hexalith-folders-workers-app-token` secret's `token` key, and to perform the stream read and conditional derived-row erase above, to patch the Workers subscription Component, and to scale/restart the selected deployments. Normal service invocation to Workers remains denied: its Dapr policy has no allowed callers. Do not add a Dapr allow rule or forward the sidecar port. Restrict the port-forward to loopback and close it when repair finishes.

   Authenticate every maintenance request and local `POST http://127.0.0.1:18080/folders/events` with the existing per-workload app-channel token in the `dapr-api-token` header. Retrieve that token into the maintenance client's memory using the approved Kubernetes secret API; never print it, put it in a shell argument/history, store it in a replay file, enable HTTP header tracing, or include it in evidence. The application and sidecar use the same `hexalith-folders-workers-app-token` secret. Missing or wrong tokens must return 401 and leave the derived row unchanged; verify denial before submitting authenticated repair events. A public Folders bearer token cannot authorize this connection.

   For each digest-verified `StreamReadEvent` in order, send its exact retained `payload` bytes (base64-encoded as the callback envelope requires) and stored `eventTypeName`, `sequenceNumber`, `messageId`, `serializationFormat`, `metadataVersion`, and `payloadVersion`. Set `domain` to `folders`, `tenantId` and `aggregateId` to the stream-read request identity, and copy `timestamp`, `correlationId`, and `causationId` where present. Never synthesize a grant or edit retained payload bytes.
5. Verify each callback succeeds before sending the next event. A sequence gap, conflicting replay, unsupported version, or identity mismatch returns a failure and leaves authorization unavailable. Investigate the retained stream; do not skip the event.
6. Read the permission row and actor head again. Restore the prior `subscriptionScopes` value on `folders-workers-pubsub`, restart Workers and wait for rollout completion, then restore the saved Folders replica count and gateway ingress only when the row's `LastSequence` equals the actor head, the row identity matches the tenant and actor, and the rebuilt grants match the retained ACL events. If new events arrived during repair, continue replaying the new retained range until current.

The `/folders/events` callback folds permission events on each delivery, so an acknowledged retained envelope can rebuild a missing derived row. Its regression test exercises the actual token-authenticated maintenance route through an SDK eraser test double: missing/wrong token returns 401 without changing the persisted test row, an outdated ETag returns 409, and a valid conditional reset followed by exact retained replay removes a stale override. These are HTTP route and persisted-state tests, not a live Kubernetes repair exercise or proof of backend Dapr ETag behavior. A live repair additionally requires the pause and operator permissions above, the actual EventStore SDK/Dapr eraser, and actor-head equality before restoring access. Public Folders REST access alone cannot replay or erase permission rows.
