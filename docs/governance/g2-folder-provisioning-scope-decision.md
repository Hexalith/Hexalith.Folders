## Provisioning design investigation

Use a separate create-only operation through the EventStore Folder actor. A new request targets an absent owner identity, binds the deterministic task-step key and intent to that identity, and records the restricted access mode and provision receipt with the create event. An authorized equivalent retry resolves the receipt from committed history before checking the first-create precondition. An incumbent stream or changed intent yields a safe conflict. A display-name lookup cannot select an existing Folder. The current generic creation path derives a Folder identity from the Tenant and idempotency key and does not reserve display names. An owner-wide name uniqueness rule would change the existing creation contract and requires its own decision.

`FolderCreationService` already checks the Organization grant and reauthorizes before append. `EventStoreFolderEffectivePermissionsReadModel` combines Organization baseline grants with Folder overrides. The provisioning mode needs to exclude inherited grants and seed explicit read and manage grants for the original actor in the authoritative create. The receipt lookup also needs fresh, exact read and manage evidence before returning the Folder identity. `FolderOwnerReadQueryHandler` currently provides the delegated metadata-read seam.

The current EventStore trusted effect origin authenticates the workload, purpose, source and target, and command bytes. It carries no verified original actor claim. Before connecting delegated provisioning, select a task-bound credential or committed admission lookup that independently binds the original actor to the Tenant, workload, task step, operation and target. Folders must re-evaluate current actor authority at the operation. Compensation disposition for the proposed create is to retain the Folder and receipt in unresolved workflows. Before recovery, fence any runtime whose projection could reapply inherited read grants to a restricted Folder.

## Decisions (2026-11-25)

On 2026-11-25 Jerome, acting as Folders Owner, settled the open provisioning questions.

- **Name collisions.** Display names are not unique. A collision is an existing Folder stream at the identity derived for the task step, or a changed request under the same step key. Both return the safe conflict and never select or modify the incumbent Folder. Two provisioned Folders can share a display name, so consumers tell Folders apart by identity. The generic creation contract is unchanged.
- **Rollback target.** Rollback after restricted provisioning is forward-only. Disable new provisioning at the same revision, freeze Folder mutations and fix forward. A previous runtime that cannot interpret the restricted access mode must not serve Folders created with it, because its permission projection could reapply inherited Tenant read grants.
- **Original actor.** Delegated provisioning verifies the original actor through the committed EventStore admission record for the task step, not a task-bound token. Folders then re-evaluates the actor's current read and manage authority at the operation.

## V1 qualification candidate (2026-11-26)

The EventStore workload gateway admits `Hexalith.Folders.Commands.ProvisionFolder` from the configured worker. The Folders server also verifies the authenticated EventStore process callback and its gateway-stamped origin. The operation consumes the committed G-1 step binding with the current fence. The v1 intent digest is the lowercase SHA-256 of the UTF-8 string `hexalith.folders.provision-folder.v1\n` followed by the trimmed display name. The admission separately binds the Tenant, actor and operation. The host grants the Folders workload the numbered step and uses the owner-derived target from the Tenant and canonical step. The command expects version zero and supplies no existing Folder. Folders checks current Tenant membership plus the original actor's current Organization grants for `create_folder`, `read_metadata` and `manage_folder_access` before first creation.

The Folder stream commits one create event with disabled inheritance and a deterministic receipt, and two explicit ACL grants for the original actor. The gateway command result carries only the owner decision. Submit each new execution attempt with its own gateway command identity. The stable task-step key addresses the committed owner effect across those attempts.

The worker checks for a prior effect before executing and recovers or verifies a committed receipt through the authenticated `POST /internal/folders/v1/provisioning/lookup` endpoint. It presents the same request under the current execution fence. Folders reads the complete committed Folder stream with native proof and checks current Tenant membership and the original actor's explicit Folder read and manage grants. Lookup returns the creation receipt with its original owner revision and access evidence tied to the current revision. An absent stream has no native proof. When a current pending step has no G-1 receipt, Folders may use the same signed EventStore stream-read grant and exact bound read proof for a zero-window read. Only the gateway's explicit HTTP 404 `missing-stream` decision establishes absence. Folders returns HTTP 204 after checking that the original actor still has the required Organization grants and the G-1 step permits execution. An empty HTTP 404 denies the caller or binding. A worker proceeds after HTTP 204, and the create-side recheck gates the append. Other failed observations are unavailable. The consumer disposition for unresolved activation is `NeedsAttention`. The Folder and receipt are retained for reconciliation.

The candidate defaults to disabled provisioning. To rehearse forward recovery, set `Folders:Provisioning:Enabled=false` and `Folders:Provisioning:FreezeMutations=true`, fence incompatible Folder servers and permission-projecting workers, then verify the restricted Folder, the receipt and incumbent history with the compatible runtime on the retained store. Drain already admitted writes before taking the recovery observation. Keep the receipt lookup configured during the freeze. Composition needs the exact worker workload, G-1 app ID, signed lookup scopes, the EventStore native stream-read enrollment, and the exact G-1 lookup and Folders receipt routes in the shared Dapr route catalog. Deployment artifacts, scope acceptance and the combined 7.1-P2 pin remain pending.
