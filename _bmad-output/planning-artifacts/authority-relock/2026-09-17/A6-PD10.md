# A6 / PD10 Decision Payload

Version: `1.0.0-candidate.1`

Authorize generation of the PD10 `/api/v2` Contract Spine candidate under all of these rules:

1. Authentication is evaluated first. All protected operations then evaluate authority availability and authority before protected-resource lookup.
2. An authenticated caller with stale, unavailable, conflicting, or incomplete authority evidence receives one non-disclosing `authority-unavailable-503` envelope with required `visibility: redacted`.
3. An authenticated caller with fresh negative authority facts receives one byte-identical `safe-denial-404` envelope. Protected v2 responses retire HTTP 403 and the `not_found`, `cross_tenant_access_denied`, and `audit_access_denied` codes.
4. `GetReadinessDiagnostics`, `GetProjectionFreshness`, and `GetTaskStatus` carry explicit folder scope; task lookup follows fresh folder authority and proves task binding to that folder.
5. `ListFolderAclEntries` requires folder `administer`.
6. `GetEffectivePermissions` permits self-inspection under folder read authority with optional task context.
7. `ValidateProviderReadiness` remains tenant-level under folder-create authority, routes endpoints through the provider egress policy, and does not invent a folder ACL before folder existence.
8. Provider, repository, ref, and task scope metadata is structured and derived from an already-authorized folder, task, or binding; raw caller locators are never authority-bearing.
9. Every error carries the required visibility field; MVP release reasons permit only approved values, and reserved post-MVP reasons reject.
10. The same candidate change regenerates OpenAPI, server, generated client, CLI, MCP, UI, parity schema/oracle, `previous-spine.yaml`, C13 inventory, documentation, and tests. It adds status-code and error-vocabulary fingerprints, maps `read_model_unavailable` to CLI 73 and `concurrency_conflict` to CLI 77/MCP `concurrency_conflict`, and removes protected not-found/authorization-outcome drift.

The corrected external surface exists only at `/api/v2`; `/api/v1` remains historical and is not production-routed. Consumer discovery must block and escalate rather than invent a migration window if a deployed external v1 consumer is found. A6 authorizes candidate generation only; it does not approve the resulting matrix digest, expose v2, publish a release, or close Story 1.17.
