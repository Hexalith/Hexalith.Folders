# Security and tenant-boundary review

**20 November 2026 · Two documentation findings**

**High — The search facade overstates the network protection in the shipped composition.** The read-mechanism paragraph at `architecture.md:167` says that production Memories requests unconditionally traverse Dapr access control and mTLS. The Server selects any configured absolute Memories base address before it considers the sidecar endpoint, across hosting environments. Consequently, checking the Dapr policy file alone cannot establish which route a rendered deployment uses. State that the supported profile requires the Dapr route and that direct addressing is reserved for test or non-Dapr profiles. Require evidence of the resolved route in supported-profile qualification. Tenant and folder authorization and per-hit trimming continue to apply independently. [Server endpoint selection](../../../../../src/Hexalith.Folders.Server/FoldersServerServiceCollectionExtensions.cs) · [Supported profile, configuration and security](../../../../../docs/deployment/supported-mvp-profile.md#configuration-and-security)

A projection author following that summary could store part of a confidential branch name. S-6 and the approved C9 rule require a tenant-sensitive default and a tenant-scoped token substituted before persistence for a confidential override. Point concern 17 to S-6 and use the approved terms there. Presentation-only redaction applies to the authorized view of tenant-sensitive metadata.
