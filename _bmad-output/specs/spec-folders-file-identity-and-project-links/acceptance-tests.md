# Acceptance tests

These are normative implementation scenarios, not tests executed during specification authoring. Use the repository's xUnit v3/Shouldly conventions. Unit tests cover domain invariants; integration tests assert actual persisted EventStore/read-model end-state, with two source instances and provider-profile enforcement where indicated. Mock call counts alone cannot prove persistence, provider controls or current-head coverage.

Fixtures use Tenant T1/T2, Project P1/P2, Folder F1/F2 and reference R. U1/U2 have distinct authority. File A has incarnation I1, parent F1/token B1 and native revision a; L1 is one committed Project link. Text aliases in this document stand for valid production-shaped identifiers. Inject clocks and controllable awaits to test races deterministically.

## Identity and lifecycle — CAP-1

| ID / suggested test method | Given / When / Then |
| --- | --- |
| AT-01 `CreateAndReplayPreserveNativeIdentity` | Given an enrolled empty source, when one create settles, is redelivered and is rebuilt after restart, then exactly one File exists with the same owner ULID, birth event, parent token and covered native revision. Concurrent duplicate delivery across two instances cannot mint a second File. |
| AT-02 `EqualBytesAndBranchesDoNotConflateFiles` | Given equal bytes at two paths or copied onto another branch/source tree, when separate creates settle, then identities/incarnations differ. A path, blob SHA, repository ID or `fv-` version supplied as a File ID cannot resolve either File. |
| AT-03 `EditChangesRevisionWithoutChangingIdentity` | Given A at revision a, when explicit edit settles, then A/I1/B1 remain and revision advances. A staged/accepted but uncommitted change is not current; an old receipt fails the final comparison. |
| AT-04 `RenameRequiresProvenContinuity` | Given A, when an explicit same-Folder rename settles, then ID/incarnation/parent token remain and only the new internal location is current. Remove/add with matching bytes without an owner continuity intent cannot produce the same conclusion. |
| AT-05 `MoveInvalidatesOldParentBindingPermanently` | Given A and L1 bound to F1/B1, when an authorized move to F2 completes, then A/I1 remain, the parent token changes and L1 under F1 is safely denied. Move A back to F1; L1 still fails. New explicit verification/link is required. |
| AT-06 `IncompleteCrossSourceMoveIsNeverCurrent` | Given a coordinated move, when the process crashes after one provider write or one File/source projection write, then neither half is current. Restarted write-side recovery either proves rollback or completes matching coverage and one active parent, with the original File ID. Query execution writes nothing. |
| AT-07 `DeleteAndRecreateNeverResurrectIdentity` | Given A/L1, when delete settles and a file with the same path/bytes is created, then A remains terminal and the new File has a new ID/incarnation. L1 never returns the recreated File before or after replay/rebuild. |
| AT-08 `ReplacementDiffersFromEdit` | Given A/L1, when explicit replacement uses different or identical bytes, then old A is terminal Replaced and the successor has a new ID/incarnation. A stale mutation cannot relabel replacement as edit; no automatic successor redirect appears. |
| AT-09 `ConflictingWritersCannotPublishTwoLocations` | Given two instances targeting one canonical repository/ref location through aliases, when concurrent creates, stale edits or a lost-fence move race, then at most one settled identity owns that location. Persisted loser/uncertain operations cannot publish current coverage. |

## Source, permission and current-head evidence — CAP-2

| ID / suggested test method | Given / When / Then |
| --- | --- |
| AT-10 `ProviderEnforcesTheEnrolledWriterBoundary` | Given each claimed supported provider profile, when another credential attempts a write, force push, ref delete/recreate or protection bypass, then the provider rejects it. After protection/authority drift or an unexpected head is detected, reads return Unavailable until explicit owner reconciliation; returning to the old head alone cannot restore trust. Retain actual provider enforcement evidence. |
| AT-11 `CoverageMustBeCommittedInitializedAndAtHead` | Given missing initialization, source/File lag, transition, gap, poison, partial batch, mixed generation, head rollback or unreadable provider head, when a read occurs, then no Current/identity is returned. An initialized complete empty source proves absence safely; a missing projection does not. |
| AT-12 `CurrentReceiptPreservesEveryNativeScope` | Given current File/source, Tenant, Organization, Folder and File-policy facts, when read under verified authority, then receipt revisions equal their native scoped values and projected positions equal native heads. Distinct Organization/Folder revisions survive aggregation; no max/global watermark or request-time replacement is produced. |
| AT-13 `EveryAuthorityChangeDefeatsTheFinalPass` | Given a paused read, when Tenant membership/disable, Organization grant, Folder ACL/lifecycle, File ACL/path policy/sensitivity, caller group/delegation revocation, File edit/move/delete or source protection changes between passes, then no earlier identity/evidence is disclosed. Run each dependency independently; a second Allowed boolean with changed revision is insufficient. |
| AT-14 `AgeOnlyTenantEvidenceCannotAuthorize` | Given StrictRead success and a Tenant observation inside the old five-minute budget, when the actual Tenant head is ahead, unknown or unsupported, then source evidence is Stale/Unavailable, never Current. A fresh timestamp without source-head equality also fails. |
| AT-15 `ObservationTimesAndDeadlineAreTruthful` | Given delayed awaited head reads and injected time, when they complete, then each ObservedAt records completion, LastVerifiedAt is the earliest required completed observation and AuthorizedAt records final evaluation. Test just inside/at/outside two seconds, negative/future times and an already-consumed upstream deadline; overdue or inconsistent evidence has no identity/receipt and causes no retry. |
| AT-16 `FileAuthorityAndFailuresDoNotLeakExistence` | Given absent, denied, T2-owned, wrong-parent, hidden/sensitive, directory, deleted and replaced targets, when read as U1, then safe denial has identical transport status/body/headers without a target-specific reason. A Folder grant alone cannot authorize a mismatched File. Dependency faults yield fixed non-current output with no exception/provider details. |

## Verified registration — CAP-3

| ID / suggested test method | Given / When / Then |
| --- | --- |
| AT-17 `RegistrationConsumesAnExactCommittedHandoff` | Given a current verified target, when owner verification commits, Projects commits a link carrying that pointer and registration completes, then persisted binding contains the exact full scoped key and immutable target. No Current binding exists between those commits; Projects reference state alone cannot supply it. |
| AT-18 `VerificationPointerIsNotAuthority` | Given an uncommitted, foreign, forged or copied verification/event pointer, mismatched Project/reference/Folder, changed File revision/incarnation/parent token or missing link-action authority, when registration runs, then no binding commits. The same actor's old successful verification cannot bypass current checks. |
| AT-19 `RegistrationScopesAndConflictsAreExact` | Given R used in P1 and P2, and equivalent identifier text in T2, when each registers, then the bindings remain separate. Conflicting target/pointer registration for L1 fails without overwrite; ambiguous tuple encodings cannot collide. Persisted reference-boundary and owner ULID validation reject malformed/oversized IDs without truncation or trimming. |
| AT-20 `RegistrationCrashAndReplayConverge` | Given interruption before/after owner verification, Project link commit, binding commit or command acknowledgement, when the write workflow resumes across two instances with original IDs, then one binding results, no File/link ID is reminted and incomplete work never appears Current. Cancellation after commit leaves recoverable durable state. |
| AT-21 `NewHandoffPreservesOldProjectEventReaders` | Given old/new Projects link payloads and consumers, when serialized/replayed, then old positional fields keep their meaning and the new optional verification pointer is tolerated. Missing/null pointer is legacy, not current mapping. Preserve native envelope link IDs through projection/rebuild; a missing optional SDK MessageId cannot be synthesized into an instance. A compatibility failure blocks adoption until an additive version is specified. |

## Lookup, invalidation and safe integration — CAP-4

| ID / suggested test method | Given / When / Then |
| --- | --- |
| AT-22 `LookupNeedsOnlyScopedOpaqueIdentifiers` | Given L1 and current owner/Project authority, when lookup uses Project/reference/link instance and envelope Folder, then it returns only the exact FileIdentity, ProjectLinkIdentity and scoped receipt allowlist. No path/workspace/provider locator or label is requested/returned. Same-Folder rename is followed without changing the binding. |
| AT-23 `UnlinkRelinkCannotReuseTheEarlierInstance` | Given L1, when unlink commits and R is linked again as L2 to A or another File, then L1 is safely denied and only separately verified/registered L2 can succeed. Test unlink racing registration, delayed revocation, old link redelivery and replayed unlink after L2; none can resurrect L1 or revoke L2. |
| AT-24 `ProjectAndBindingHeadsPreventRevocationWindows` | Given Folders' mirror still shows L1, when the actual Project head contains unlink/archive or a replacement link, then lagging membership is non-current and cannot disclose A. Independently lag the owner binding projection behind its own revocation/head while Project/File are current; lookup still fails. Final-pass Project permission/membership/binding changes fail likewise. A complete authorized Absent/Unlinked observation safely denies; missing coverage cannot be treated as absence. |
| AT-25 `TerminalFileAndParentChecksBeatDelayedMaintenance` | Given an old binding projection with no invalidation yet, when authoritative File state has moved, deleted or replaced, then lookup denies based on the immutable target comparison. Rebuild or reintroducing identical bytes/old Folder cannot revive the binding. |
| AT-26 `LegacyUnmappedReferencesStayUnavailable` | Given an authorized legacy reference without recoverable owner verification/mapping, when lookup runs, then Unavailable carries no File identity. No path/hash conversion, history rewrite, source ingestion, automatic relink or NoMatch occurs. Unauthorised callers learn no reference existence. |
| AT-27 `CallerContextCannotTransferOrBeForged` | Given a receipt/binding produced under U1/P1, when another actor/Tenant/workload/delegation or a request with forged payload/header authority, missing SDK context, wrong audience/action, mismatched exact query object or expired/revoked authority uses it, then no permission transfers. Exercise the supported authenticated gateway with production issuer/profile qualification when available; local test signing alone is insufficient. |
| AT-28 `MetadataReadsRetrieveNoContentAndPersistNothing` | Given content/path/workspace/detail/search/inspection-audit APIs instrumented to fail and protected sentinel data, when successful, denied, stale, unavailable and cancelled reads run, then none of those APIs is called; response/error/log/trace fields remain allowlisted. Actual before/after domain, mapping, read-model, repair and inspection-audit stores are unchanged. Only ordinary platform security-denial auditing is permitted. |
| AT-29 `CancellationAndMalformedEvidenceFailClosed` | Given cancellation at each awaited source, malformed/unknown/duplicate payload fields, contradictory envelope scope, paging, corrupt native tuples, unsupported schema/event versions, zero/empty revisions or identities attached to non-current outcomes, when lookup/read executes, then cancellation propagates or the defined safe field-free failure occurs. No partial identity, fallback, retry, checkpoint advancement or read-side repair results. |
| AT-30 `SourceAcceptanceDoesNotChangeParentOrLegacyContracts` | Given existing FolderOwnerReadResult and legacy consumers/routes, when the source capability is delivered, then constructor/deconstruction/numeric Outcome behavior and legacy routes remain intact. Outcome-only or absent/null native evidence cannot satisfy new source admission. Verify parent handlers, scoring, RTI and dependency pins are outside this delivery's diff. |
