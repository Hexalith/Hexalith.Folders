## Intent

Make the results of a dev/test repository append reliable for callers that inspect state, idempotency, counters and projection freshness.

- DW-8. Given concurrent equivalent commands evaluated at distinct times, when writers append to the same folder with the same idempotency key, then one event is published and every replay matches its fingerprint.
- DW-310. Given a folder append counter at the 32-bit boundary, when another event is appended, then the diagnostic count remains exact and can still be reset.
- DW-311. Given multiple read models for one folder, when their observation times differ or the clock moves backwards, then each projection retains its own non-decreasing watermark.
- DW-312. Given an organization provider binding append in progress, when other threads read the state, ledger or append count, then each read observes a consistent publication. Equivalent and conflicting retries preserve the winner.
- DW-313. Given a developer using the organization repository, when they read its synchronization contract, then they can identify the state covered by its gate and the scope of that guarantee.

</frozen-after-approval>
