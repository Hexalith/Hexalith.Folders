## Intent

**Problem:** Rank-4 milestone `1.17-GENERATE` has approval to generate, but the repository still exposes a v1-only Contract Spine and legacy authorization/error behavior that cannot serve as the digest-bound PD10 v2 candidate for A6b.

**Approach:** Generate the complete v2 contract, server, SDK, CLI, MCP, UI, previous-spine, C13, documentation, drift-gate, and focused-test candidate set in lockstep, then emit an exact-path/SHA-256 conformance manifest without exposing or approving it.

## Boundaries & Constraints

**Always:** Preserve v1 and historical OQ3 evidence; cover exactly fourteen canonical access states and all eleven protected families; authenticate and establish fresh authority before any protected lookup/read; prove folder scope and task binding; revalidate freshness immediately before task-mutation effects; use canonical 401/404/503 envelopes with closed visibility/action/error/exit/failure vocabularies; keep generated files generator-owned; preserve all pre-existing worktree changes. Emit the one six-field authorization audit before downstream dispatch; if the replaceable sink fails, propagate failure without protected observation or mutation and do not retry the audit. Stop and escalate if a deployed external v1 consumer is discovered.

**Never:** Route or publish v2; close Story 1.17 or any ordinary story; infer or record A6b/A8; remove the execution hold; modify/regenerate `sprint-status.yaml`; generate OQ5–OQ13 runtime evidence; edit generated SDK/parity rows by hand; alter deployment/release exposure.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|---------------|----------------------------|----------------|
| Unauthenticated | Any protected v2 operation | No protected lookup; canonical `401` | `authentication_failure` / `authentication_required` / `check_credentials` / `redacted` |
| Fresh negative authority | Wrong tenant, revoked, hidden, absent, disabled, unknown, or insufficient scope | Zero protected reads; byte-equivalent `404` | `tenant_access_denied` / `resource_unavailable` / `no_action` / `redacted` |
| Unusable authority | Stale, unavailable, conflicting, or incomplete evidence | Zero protected reads; retryable `503` | `read_model_unavailable` / `projection_unavailable` / `retry` / `redacted` |

| Adapter conflict | `concurrency_conflict` | CLI exit `77`; MCP kind `concurrency_conflict` | No legacy caller-visible outcome |
| Read-model outage | `read_model_unavailable` | CLI exit `73`; closed MCP mapping | Retry metadata retained without disclosure |
| Audit sink failure | Direct allow/deny record cannot be written | Abort before protected dispatch or mutation; no duplicate attempt | Propagate through existing host failure handling |

**Acceptance Criteria:**
- Given a candidate allow or deny, when audit persistence succeeds, then exactly one six-field record of the final protected outcome exists before protected dispatch, including task-folder binding where `NotBound` is deny and canonical `404` and `Unavailable` is canonical `503`; a prior allow is not the only record. When audit persistence fails, no protected read, gateway call, repository mutation, provider effect, or duplicate audit attempt occurs.
- Given task-mutation authority is revoked, stale, or delegated inconsistently after initial checks, when the final effect boundary is reached, then canonical denial/unavailable behavior occurs and no effect is applied.
- Given any candidate request or error response, when validation/projection runs, then schema-owned values, operation identity, status, tuple fields, token kinds, and exact detail keys agree or fail closed. Malformed or unexpected JSON, including on an operation with no root schema discriminator, is that operation's canonical validation response, and `JsonNode.Parse` does not escape after an allow audit.
- Given an oversized body, when the caller has not been authorized, then the response is not `413` and the oversized body is not buffered to discover the limit; authentication and the authorization audit precede input-limit disclosure.
- Given a transport body with neither `Content-Length` nor `Transfer-Encoding`, when the operation requires a body, then the body is not rejected for that absence; when the operation does not accept a body, then the body is not accepted for that absence.
- Given `CreateRepositoryBackedFolder`, when the body names a `folderId` that does not yet exist, then authorization is folder creation of that id and the outcome is not a fresh absent-folder denial.
- Given an identifier accepted by the uppercase-capable v2 opaque-identifier grammar during a request, when seam state has ended, then stream names, command validation, and projection rebuild accept that same identifier.
- Given the historical handler throws before a status is captured, when the seam handles that exception, then the response is the canonical fail-closed authority-unavailable response.
- Given any one of the 49 operations, when its accepted parameters, body rules, historical dispatch, and failure producers are enumerated, then the generated contract admits every reachable response and no unreachable parameter value or tuple; malformed or unknown downstream output becomes one declared fail-closed response.
- Given CLI or MCP input, when an optional argument is omitted versus explicitly blank or a required body/freshness value is invalid, then omission alone selects defaults and supplied invalid input returns the established usage failure before dispatch.
- Given generation and focused/full gates complete, when the manifest is reproduced, then all candidate paths and digests match while v1, OQ3, routing, holds, approvals, and sprint status remain unchanged.
