## Actual candidate loader

Candidate [RunTopology.ComposePlatform](https://github.com/Hexalith/Hexalith.Builds/blob/e171c5a788eab183b32683431b084198c9b8d373/src/hosts/Hexalith.Builds.Module.AppHost/RunTopology.cs#L272-L305) installs `AssemblyLoadContext.Default.Resolving`, tries `<modelDirectory>/<requested-simple-name>.dll` in that callback, then uses `Default.LoadFromAssemblyPath(modelPath)`. It reflects the exact `PlatformAppModel.ComposeRun` method and invokes it. There is **no isolated model context and no model-side AssemblyDependencyResolver**. UI/descriptor loaders elsewhere in Builds do not govern this path. The model's `.deps.json` is not explicitly added to the host's resolver.

`CompositionCommandOptions` selects packaged `g4-host` unless `HEXALITH_G4_APPHOST` overrides it. `CompositionEngine` launches that AppHost for validation and startup. `AppHostRunner` creates a real Aspire builder and adds Dapr before composition. **`--validate-platform` invokes ComposeRun** and therefore cannot substitute for the proposed no-entrypoint experiment; model composition can perform probes and write generated state.

The host's actual deps file selects Aspire13.6.3, EventStore.Aspire3.127, Redis3.4.5/assembly3 and Tooling4.38. Under [.NET default probing](https://learn.microsoft.com/en-us/dotnet/core/dependency-loading/default-probing), host deps configure TPA/application paths, which precede the model-directory fallback and can take precedence over a Default-context path load. One simple name has one loaded version; the ordinary cached binding rule requires loaded version at least as high as requested. [ALC rules](https://learn.microsoft.com/en-us/dotnet/core/dependency-loading/understanding-assemblyloadcontext) and the [loading algorithm](https://learn.microsoft.com/en-us/dotnet/core/dependency-loading/loading-managed) also warn that demand timing is unspecified.

Retained comparative runtime source for tag `v10.0.13` shows `BindLocked` checking version compatibility and `BindUsingPEImage` checking MVID on an existing same-name binding. The installed runtime `.version` reports `4099f83977f4d29604a9aeb971fb0a7bc1d5f699`; fetching that exact commit's source returned 404. The retained tag source is **not an attestation that the installed binaries were built from it**. Runtime binaries are separately hash-bound. Primary source: [binder implementation](https://github.com/dotnet/runtime/blob/v10.0.13/src/coreclr/binder/assemblybindercommon.cpp).

## Exact proposed experiment and enforcement

The plan binds **238 host files** to the existing signed package and **45 model files** to the verified compile archive. It copies them into a fresh private directory and compiles only the supplied LoaderProbe using the pinned SDK's C# compiler and existing reference pack. There is no package restore, model rebuild, new feed, dependency update, changed catalog, custom map or signed run plan.

Two fresh processes use the **unchanged host deps/runtimeconfig**, the same Default-context model-directory resolver and the same retained model. The first has no deliberate EventStore preload; the second explicitly requests host3.127 first. Both log actual initially loaded assemblies and probing state. They inspect only the exact ComposeRun method metadata, then demand the named Redis identities, optional ServiceDefaults identity and finally EventStore3.128. Optional demands are labelled experiments, not representations of Parties' path. No library method, constructor, health check or application entrypoint is explicitly invoked.

The final EventStore demand is expected to expose a conflict. Its exit10 records a binding failure and permits only the second predetermined case. Exit0 is only a binding observation; exit20, unexpected failure, timeout or any gate/isolation drift stops the remaining work. No retry, patch or alternate version is permitted. A pass does **not** establish API behavior, complete transitive closure, real AppHost load order, Redis operations, selected-feature execution, readiness or acceptance. If a later necessary repair is established, prepare a separate exact patch with full base revisions, affected paths, provenance, risks and rollback before any application.

Before the first SDK command, the runner supplies a complete explicit environment, private CLI/cache/temp/bundle locations, `DOTNET_GENERATE_ASPNET_CERTIFICATE=false` and disabled diagnostics. It never repurposes HOME. `bwrap` mounts external files read-only, exposes only the new private directory writable, unshares PID/network namespaces and masks `/run`; an x86_64 seccomp filter denies socket/connect/socketpair/io_uring setup and rejects other ABIs. This also blocks pathname Unix sockets, which an unshared network namespace alone would not prevent. If these mechanisms are unavailable, stop; no unsandboxed fallback is authorized. The helper has not been compiled and sandbox support has not been tested.

Before each compiler/probe launch, assert `dotnet --version` equals10.0.402 and immediately rehash the executable/global.json/compiler/runtime/reference inputs. Retain `--info` and asserted MSBuild version18.9.15.50611. The runtime probe requires.NET10.0.13 and records actual framework selection/TPA; newly installed framework directories cause a stop. All SDK commands are bounded30seconds, the compiler and each probe60seconds, with TERM then5seconds before KILL. These are new enforceable gates, not a retrospective pass for the historical build.

Retain before/after certificate-store directory/lstat metadata only, all actual argv/cwd/explicit environment, exit/stdout/stderr hashes, host traces, assembly identity/path/hash/MVID/context, callback/exception logs and timestamped raw process observations. Sampling every200ms records PID/PPID/PGID/starttime and post-exit survivors; transient children may be missed. Kernel containment is distinct from this sampling evidence. A certificate installation/trust message or metadata drift stops the lane. No certificate contents are read, no trust requested, and no real store is cleaned.

Outputs remain under `/tmp/story117-cli438-loader-20261026-*` until an actual execution receipt/archive/member manifest is sealed. Exact output filenames and cleanup conditions are in the plan. Retain failures. Cleanup may remove only that newly created directory after inventory, verified archival and process checks; never previous qualification directories, shared caches, certificates or source files.
