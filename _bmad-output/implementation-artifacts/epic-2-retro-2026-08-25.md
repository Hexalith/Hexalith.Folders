## Findings

### Finding 1 — The archive story shipped green and unwired; only round-2 review caught it (accept as-is; lesson codified)

Story 2.8 recorded a full green suite at close — `dotnet test
Hexalith.Folders.slnx` at **623 passed, 1 skipped, 0 failed**
(`2-8-archive-folders-with-audit-preservation.md`, Debug Log References) —
while no production `/process` callback invoked the archive gate at all.
`docs/adrs/0001-folder-domain-processor-persistence.md` states it plainly:
"Story 2.8 added archive command validation, decision-bound idempotency,
ACL/policy checks, and append-conflict reread inside `FolderArchiveTenantGate`,
but round-2 review found that no production `/process` callback invoked the
gate." A whole extra story — 2.8b — existed only to repair that.

The tests were green because they exercised the gate directly and the endpoint
through a mocked `IEventStoreGatewayClient`. Nothing in the suite crossed the
REST → gateway → `/process` → processor → gate → persistence boundary.

**Disposition: accept as-is.** The instance was fixed by 2.8b, and the lesson is
already codified as a standing project rule: `_bmad-output/project-context.md`
now requires every mutation-command story to include an in-process integration
test that does **not** mock `IEventStoreGatewayClient`, and names this episode
directly — "that is the 2.8/2.8b 'green tests, broken production wiring' trap."
This is the best outcome an epic defect can have: a one-line rule that makes the
same failure impossible to repeat silently.

**Upstream lesson:** already applied. No new action item.

### Finding 2 — Story-level negative scope summed to an epic-level capability that did not exist at close (fix now — process)

Epic 2's own outcome statement (`epics.md:827`) claims: "Tenant administrators
and authorized actors can create folders, manage access, inspect effective
permissions, archive folders, and receive safe authorization evidence."

At `d179d92`, the Server exposed exactly five route mappings, all in one file
(`git show d179d92:src/Hexalith.Folders.Server/FoldersDomainServiceEndpoints.cs`):
`POST /process`, `POST /project` (501), `GET .../effective-permissions`,
`POST .../archive`, `GET .../lifecycle-status`. There was **no** `POST
/api/v1/folders` and **no** `.../acl` route — even though the Contract Spine at
that same commit declared both (`hexalith.folders.v1.yaml:36`, `:286`, `:355`).
`FolderDomainProcessor` at that commit dispatched **only** `ArchiveFolder`;
every other command returned `UnsupportedCommandType`
(`git show d179d92:src/Hexalith.Folders.Server/FolderDomainProcessor.cs:50-53`).

So at Epic 2 close, no actor could create a folder or grant/revoke access
through any surface. Those paths landed on 2026-06-23 in commit `2df3c41`,
"feat(story-8.1): Implement the 8 missing Bucket-A canonical REST server
routes" — a different epic, a month later, found by the Epic 5 parity audit.

**This is not a story defect.** Stories 2.3 and 2.4 declared this scope-out
explicitly and honestly: 2.4 AC15 — "it exposes no mutation path outside the
domain command/aggregate surface introduced here"; 2.3 AC12 lists the same
exclusions. Each story did what it said. The gap is structural: no story in the
epic owned "make Epic 2's commands reachable," and nothing checked the epic's
own outcome sentence against the sum of its stories.

**Disposition: fix now (process).** The instance is closed by Story 8.1. The
prevention is an epic-close reachability check — see Action Item 1.

### Finding 3 — ADR-0001's story-scoped persistence decision became a system-wide one, and is now Epic 12 (defer — owned)

`docs/adrs/0001-folder-domain-processor-persistence.md`, dated 2026-05-20 and
scoped "Accepted for Story 2.8b implementation," chose Option B: the Folders
gates keep persistence ownership through `IFolderRepository`, and
`FolderDomainProcessor` returns `DomainResult.NoOp()` for accepted mutations
"so the EventStore framework does not double-write folder events."

The ADR was locally well-reasoned and explicitly recorded its own tradeoff:
"This deliberately bypasses EventStore framework event persistence for folder
mutation events... so a later architecture story can revisit Option A or C
deliberately."

Three months on, `InMemoryFolderRepository` is still the sole implementation of
`IFolderRepository` (`src/Hexalith.Folders/Aggregates/Folder/`), registered as
the production default at
`src/Hexalith.Folders/FoldersServiceCollectionExtensions.cs:58`
(`services.TryAddSingleton<IFolderRepository, InMemoryFolderRepository>()`).
It has grown from 208 lines at Epic 2 close to 613 today. Every folder mutation
in the system lands in a process-local dictionary.

The architecture now names this decision explicitly as production-blocking —
`epics.md:251`, AR-CURRENT-03: "Production must replace the ADR-0001 NoOp
repository and `/project` 501 with an EventStore-backed `IFolderRepository`,
durable replay, and a bootable deployed host." Epic 12 Story 12.1
(`epics.md:2614-2624`) owns exactly that, and is `backlog`.

**Disposition: defer — already owned.** No new item; this finding exists to
record the provenance, so Epic 12's scope is understood as unwinding an Epic 2
decision rather than adding new work. The honest read is that Epic 2's ACs
saying events are "persisted" and ACL changes "recorded and projected" were met
in the in-process sense and not in the durable sense, and that gap was
deliberate and documented from day one — not discovered later.

### Finding 5 — Three sibling gates from one epic resolve the same append outcome two different ways (fix now — latent, Epic 12 hazard)

Epic 2 created three near-identical gate classes. `FolderAccessTenantGate` and
`FolderArchiveTenantGate` both route `FolderAppendOutcome.AppendConflict` into a
`ResolveAppendConflict` helper that re-reads state and returns deterministic
no-op/duplicate evidence
(`FolderArchiveTenantGate.cs:126-127`, `:142-153`).
`FolderCreateTenantGate` maps the same outcome straight to
`FolderResultCode.AppendConflict` with no re-read
(`FolderCreateTenantGate.cs:125-126`).

Story 2.3's own AC9 asks for the archive/access behavior: when create "races
another same-folder create, then the command returns deterministic
duplicate/already-exists evidence." The create gate returns `append_conflict`
instead.

Two qualifiers keep this honest, and both matter:

1. **It is unreachable in production today.** `InMemoryFolderRepository` never
   returns `AppendConflict` — it emits only `FingerprintMatched`,
   `FingerprintConflict`, and `Appended` (`InMemoryFolderRepository.cs:134-149`).
2. **The current behavior is deliberately pinned by a test** —
   `FolderCreationIdempotencyTests.cs:133-144`,
   `AppendConflictShouldReturnStableEvidenceWithoutSecondEvent`, asserts
   `result.Code.ShouldBe(FolderResultCode.AppendConflict)`.

So this is not a live bug and not an oversight. It is a divergence that becomes
reachable the moment Epic 12 Story 12.1 swaps in a durable repository that
*can* return `AppendConflict` — at which point create will surface a different
result code from its two siblings for the same race, and a test will defend the
inconsistency.

**Disposition: fix now — but scheduled into Story 12.1, not before it.**
See Action Item 3.

### Finding 6 — Epic 2 seeded the two files that later epics grew into god-files (defer — confirm Epic 11 ownership)

Epic 2 created `FoldersDomainServiceEndpoints.cs` (it did not exist at
`a2a301e^`) at **796 lines**. Today it is **6,560 lines** — one `public static
class`, one `MapFoldersDomainServiceEndpoints` method, **37** route mappings.
`FolderDomainProcessor.cs` went from **219** lines to **1,464**, its dispatch a
flat if-chain over 16 command types (`FolderDomainProcessor.cs:106-171`).
`FolderCommandValidator.cs` went 453 → 975; `FolderAggregate.cs` 243 → 922.

No single story did anything unreasonable; each added its own routes and its own
`ProcessXxxAsync` to the file the previous story had established. That is
exactly the growth pattern no per-story review can see.

Separately, the gate skeleton — `Handle`, `HasCompetingClientTenant`,
`EvaluateAcl`, `Map(TenantAccessOutcome)`, `ResolveAppendConflict` — is now
re-implemented across **five** classes with no shared base or helper: Epic 2's
`FolderCreateTenantGate` (8.3 KB), `FolderAccessTenantGate` (12.2 KB),
`FolderArchiveTenantGate` (12.1 KB), plus later `OrganizationAclTenantGate`
(5.2 KB) and `OrganizationProviderBindingTenantGate` (6.1 KB). Epic 2 wrote the
template three times; later epics copied it twice more.

A smaller divergence sits inside the same folder from the same epic:
`FolderCreateTenantGate` uses an explicit constructor with backing fields
(`:5-21`) while its two siblings use primary constructors (`:5-8` in each) —
three files, one epic, two idioms.

**Disposition: defer — confirm ownership.** Epic 11 Stories 11.4
(`consolidate-server-transport-envelope-and-route-helper-duplication`) and 11.5
(`consolidate-domain-provider-duplication...`) plausibly cover this, both
`backlog`. See Action Item 4.
