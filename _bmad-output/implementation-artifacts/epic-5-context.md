# Epic 5 Context: Cross-Surface Workflow Parity

## Goal

Ensure REST, generated .NET SDK, and `Hexalith.McpCli` CLI and MCP callers execute the same canonical repository-backed workspace lifecycle—including mixed-surface handoffs—with identical operation identity, authorization, idempotency, lock semantics, structured errors, status vocabularies, and metadata-only audit behavior. Four-surface parity is verified through a generated parity oracle and deployed persistence rather than manual comparison, while CLI and MCP delivery migrates from frozen legacy SDK wrappers onto `Hexalith.McpCli` over the EventStore Gateway and retires `Hexalith.Folders.Cli` and `Hexalith.Folders.Mcp`.

## Requirements & Constraints

- **Four-surface parity denominator:** Every Contract Spine operation must have one row in `parity-contract.yaml` declaring REST, SDK, CLI, and MCP support. Core lifecycle and tenant-administration operations must pass on all four surfaces with zero material deltas for both GitHub and Forgejo. Any operation omitted or deferred on CLI/MCP requires an owner-approved inventory `withdraw` or `defer` plus a product-approved parity-oracle declaration—never silent absence or fallback to legacy binaries.
- **McpCli as sole target CLI/MCP surface:** All new CLI/MCP delivery and release-qualifying parity evidence must execute through `Hexalith.McpCli` heads over the EventStore Gateway. Legacy `Hexalith.Folders.Cli`, `Hexalith.Folders.Mcp`, and `AdapterCore` are frozen compatibility surfaces (safety/continuity fixes only) and cannot satisfy Epic 5 completion or four-surface MVP claims.
- **Mixed-surface task handoff:** A task identified by a caller-supplied task ID (bound at workspace preparation to principal/delegation, tenant, folder, and workspace) must move across REST, SDK, and both McpCli heads while preserving task identity, lock ownership, idempotency outcomes, correlation IDs, and audit trail.
- **Deny-before-access authorization:** Both REST and Gateway paths evaluate authentication first (401), then authority availability (non-disclosing retryable 503 when tenant, membership, delegation, or ACL evidence is stale, incomplete, or unavailable), then layered tenant/folder ACL (`read`/`write`/`administer`), revocation, and task/workspace/lock scope, and only then protected-resource lookup. Fresh negative facts (unauthorized, cross-tenant, absent, hidden, revoked) return byte-identical safe denials (`tenant_access_denied` / `resource_unavailable`, 404 on v2; no protected 403 or `not_found`) with zero protected reads and zero mutations. Envelope tenant and actor fields are comparison inputs against verified authority, never trusted authority.
- **All-mutations idempotency and read rejection:** Every mutating operation requires a caller-supplied idempotency key evaluated by tenant-scoped intent equivalence (operation, canonical target, normalized semantic payload/options, policy version, delegated task scope; excluding correlation, auth, and transport metadata). Unexpired equivalent replays revalidate current authorization and return the same logical result without duplicating events, writes, repositories, commits, or audits; conflicting intent returns `idempotency_conflict`; expired keys return non-retryable `idempotency_key_expired` for both equivalent and conflicting reuse and never execute as new work. Replay records retain 24 hours (non-commit mutations) and 7 years (commits), with consumed-key tombstones retained for tenant lifetime plus 400 days. Non-mutating reads reject idempotency keys before source access.
- **Canonical state, errors, and metadata-only boundaries:** All surfaces preserve exact lowercase workspace lifecycle states (`requested`, `preparing`, `ready`, `locked`, `changes_staged`, `dirty`, `committed`, `failed`, `inaccessible`, `unknown_provider_outcome`, `reconciliation_required`), separate lock states (`unlocked`, `locked`, `expired`, `stale`, `revoked`), and structured errors (`category`, `code`, `message`, `correlationId`, `retryable`, `clientAction`, `details.visibility`). Events, logs, traces, metrics, projections, audit records, errors, and Gateway metadata reads must never leak file bodies, diffs, raw secrets, provider tokens, or unauthorized paths.
- **Content bounds and provider safety:** Inline file mutations support up to 262,144 decoded bytes (larger files up to 1 MiB require an approved staging/stream contract or an inventory `defer`). Live context reads enforce path policy and bounds (100 paths, 2,000 tree entries, 500 search/glob hits, 262,144-byte single range, 1,048,576-byte aggregate response, 2s server execution) with explicit `isTruncated` signaling and no silent range truncation. Provider bindings accept credential references only, authorize before any provider egress, and keep ACL grant and revoke distinct.
- **Deployed end-state proof:** McpCli enrollment stories require real deployed composition tests asserting persisted state-store end-state across success, denial/wrong-tenant, replay/conflict/expiry, lock contention/expiry, provider failure, timeout/unknown reconciliation, and input boundaries. Fakes, mocks, NoOps, seed-only data, safe-empty stubs, and legacy binary outputs cannot prove completion.

## Technical Decisions

- **Contract Spine and SDK:** The OpenAPI 3.1 v2 Contract Spine in `Hexalith.Folders.Contracts` is the canonical schema/operation authority. `Hexalith.Folders.Client` is generated via NSwag (with payload idempotency-hash helpers) against REST routes; convenience helpers must not add lifecycle semantics absent from the Spine or target v1.
- **Decorated McpCli Contracts:** `Hexalith.Folders.Contracts` declares `[assembly: HexalithModule("folders", ...)]` and one decorated public Command or Query type per owner-approved agent-eligible operation (one type per file under `.Commands`/`.Queries`, nonblank description, `Domain = "folders"`, aggregate routing, and `[HexalithIdentifier]` properties), referencing only versionless `Hexalith.McpCli.Abstractions`. The chosen module identifier kind must round-trip all folder, workspace, task, and provider-binding IDs without silent conversion. No Folders-specific McpCli host or adapter code is permitted.
- **Gateway command and query dispatch:** Decorated Commands explicitly map to existing `Hexalith.Folders.Commands.*` wire names (never derived `Contracts.Commands.*` names). `/process` admission accepts McpCli uppercase ULID message/correlation IDs without lowercasing aggregate IDs, keeps caller idempotency keys independent of generated message IDs, and enforces task/workspace context from payload or allowed envelope extensions (failing closed if missing or mismatched). Decorated Queries dispatch through registered `IDomainQueryHandler` implementations over durable projections (never `/project`), applying single per-operation freshness and explicit payload-vs-envelope paging/filter precedence (rejecting conflicting or unsupported combinations).
- **Ownership boundary:** `Hexalith.McpCli` owns CLI exit codes, MCP result envelopes, error documents, and profiles. Folders owns operation semantics, Gateway admission/authorization/query handlers, Contract Spine drift gates (failing builds when decorated types diverge from mapped Spine fields, required flags, or bounds), and the parity-oracle mapping linking canonical Folders errors to each `mcpcli_operation`.
- **Trusted idempotency and correlation:** A registered Folders server adapter derives the versioned canonical intent descriptor after auth/validation; an EventStore admission actor partitioned by tenant and HMAC-SHA-256 key digest atomically serializes reservation, replay, conflict, and expiry compaction across replicas. Public opaque IDs use 16–128 ASCII chars (`^[A-Za-z0-9][A-Za-z0-9_-]{15,127}$`). Caller-supplied `X-Correlation-Id` propagates unchanged across REST, SDK, Gateway envelopes, projections, and audit; omitted values generate a fresh ULID.
- **Oracle and lockstep retirement:** `tests/fixtures/parity-contract.yaml` (schema-validated and symmetrically checked against `previous-spine.yaml`) drives xUnit theory tests and records `mcpcli_operation` alongside legacy `cli_exit_code`/`mcp_failure_kind` columns. Retiring the legacy binaries removes `Hexalith.Folders.Cli`, `Hexalith.Folders.Mcp`, `AdapterCore`, their test projects, solution/NuGet/CI entries, scaffold/conformance pins, and legacy oracle columns in one lockstep change while keeping `mcpcli_operation`, preserving Story 5.2–5.7 history, updating docs to McpCli profiles, and deprecating the published legacy NuGet packages.

- **Upstream epics:** Epic 1 supplies the v2 Contract Spine, generated SDK, authorization matrix, and parity oracle (Stories 5.1, 5.4–5.5, 5.12). Epics 4 and 12 supply durable prepare/lock (Story 4.19 → 5.8), durable file/context/commit and all-mutations idempotency (Stories 4.20, 4.21, 12.6 → 5.9), durable folder repository (Story 12.1 → 5.10), and authorized content read-back alignment (`HXF-MCP-001` → 5.14).
- **External McpCli gates:** Owner-approved eligibility and accepted legacy behavior-loss decisions (local-file input, `--allow-auto-key`, credential precedence, MCP resources, and restricted/mixed operation classification), the staging contract for content >262,144 bytes (McpCli Story 5.2), `EXT-MCPCLI-FOLDERS-ENROLLMENT`, and `EXT-MCPCLI-FOLDERS-RETIREMENT-GATE`.
- **Downstream:** MVP release acceptance and Epic 7 consumer documentation depend on Story 5.11 parity evidence and Story 5.15 retirement verification.
