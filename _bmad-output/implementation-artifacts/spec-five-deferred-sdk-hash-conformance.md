## Intent

Make the SDK conformance suite exercise the types and comparison rules that determine a request's idempotency hash. Existing clients must retain their current hashes.

- DW-96. Given a corpus scalar, when the SDK harness hashes it, then null, booleans, numbers and their text spellings retain their distinct canonical representations.
- DW-220. Given JSON arrays or objects, when the harness hashes them, then object properties sort recursively, array element order matters, and nested strings retain their JSON meaning.
- DW-108. Given a corpus classification, when the suite evaluates the default SDK behavior, then it checks the exact rule for that boundary and reports an unfamiliar rule with its case ID.
- DW-93. Given zeros of supported numeric types, when the public SDK hasher runs, then integer, binary32, binary64 and decimal hashes follow their established encodings, including sign and decimal scale.
- DW-99. Given binary64 subnormals with known bit patterns, when the public SDK hasher runs, then their canonical hashes preserve the supplied bits on either side of zero.
